# folio

Портфолио Yar Luchkin. Сайт на Jekyll: GitHub Pages собирает его сам после каждого сохранения, ничего устанавливать не нужно. Адрес: https://ceoofdesign.github.io/folio/

## Что где лежит

| Что меняем | Файл |
|---|---|
| Имя, первая фраза, контакты, блок About | `_data/profile.yml` |
| Выступления и статьи | `_data/notes.yml` |
| Кейсы и концепты, английский | `_work/название.md`, один файл на проект |
| Японские версии кейсов | `_work_ja/название.md`, то же имя файла |
| Подписи интерфейса на двух языках | `_data/i18n.yml` |
| Картинки | `assets/img/название-проекта/` |
| Оформление | `assets/css/site.css` |
| Игра на первом экране | `assets/js/hero-tower.js`, тексты в `_data/i18n.yml` → `games` |
| Таблица рекордов | `tools/leaderboard.gs` и `leaderboard_url` в `_config.yml` |

## Как устроен файл кейса

Сверху, между линиями `---`, лежат поля для главной и шапки кейса. Ниже обычный текст в Markdown.

```markdown
---
title: "Длинный заголовок страницы кейса"
name: "Короткое имя для главной"
kind: product          # product — основной кейс, concept — побочный проект
order: 1               # порядок на главной
state: shipped         # now подсвечивается, ещё shipped или concept
work: "Что делал, коротко"
period: "2024–2025"
scale: "1M+ users"     # главная цифра проекта
role: "Product designer"
lede: "Одна-две фразы: что сделал и зачем."
cover: "../../assets/img/project/cover.webp"
cover_alt: "Описание обложки"
thumbs:                # необязательно, две картинки под обложкой на главной
  - "../../assets/img/project/1.webp"
  - "../../assets/img/project/2.webp"
facts:                 # таблица фактов в шапке кейса, до четырёх пар
  Company: "..."
  Period: "..."
  My role: "..."
  Team: "..."
outcomes:              # итоги показываются выше описания процесса
  - "Итог, по возможности с цифрой"
outcome_note: "Необязательная оговорка про цифры"
---

## Context

Текст.

## Problem

Текст.

## What I did

- **Что.** Подробности.

![Подпись к картинке](../../assets/img/project/screen.webp)

![Левая картинка](../../assets/img/project/a.webp) ![Правая картинка](../../assets/img/project/b.webp)
```

Текст после `![` становится подписью. Две картинки в одной строке встанут рядом. Клик по картинке увеличивает её. Чтобы временно скрыть кейс, добавьте в начало файла `published: false`.

## Промпт для обычного чата с Claude

Скопируйте в чат, дальше присылайте материалы:

> Мы наполняем моё портфолио на Jekyll в репозитории ceoofdesign/folio. Кейс живёт в файле `_work/название.md`, образец полей описан в README этого репозитория. Пиши на английском, коротко и по делу: сначала что сделал и какой итог, потом контекст и процесс. Не выдумывай цифры и факты: если их нет, спроси или оставь поле пустым. На выходе дай целиком готовый файл, который я вставлю на GitHub. Картинки указывай как `../../assets/img/имя-проекта/файл.webp`.

На GitHub: открыть файл → значок карандаша → вставить → Commit changes. Новый файл: Add file → Create new file. Картинки: Add file → Upload files, в папке `assets/img/имя-проекта/`. Сайт обновится примерно через минуту.

## Важно

Сейчас обложки и скриншоты подгружаются с основного сайта и с Framer. Перед заменой основного сайта их нужно перенести в `assets/img/`, иначе они пропадут.

## Японская версия

Живёт по адресу `/ja/`. У каждого кейса есть пара: `_work/rail-ninja.md` и `_work_ja/rail-ninja.md`. В японском файле только тексты: заголовок, `name`, `work`, `period`, `scale`, `role`, `lede`, `cover_alt`, `facts`, `outcomes` и сам текст. Обложку, превью, порядок и статус японская версия берёт из английского файла. Картинки внутри текста указываются в обоих файлах.

Японские тексты пока черновые. Перед отправкой японским рекрутёрам их стоит дать на вычитку носителю. Пока вычитки нет, можно спрятать переключатель языка: `ja_published: false` в `_config.yml`.

## Игра и таблица рекордов

На первом экране игра: с крана качается экран бронирования, игрок отпускает его кликом или тапом и строит башню. Неровная посадка раскачивает башню, свесившийся экран падает и считается багом. Три бага или обрушение заканчивают партию. После неё игрок видит результат, может сохранить его с именем и компанией и сразу написать вам: письмо уже заполнено его именем, компанией и результатом. Кнопка «Records» рядом с игрой открывает таблицу лучших результатов.

Общая таблица уже подключена: Google Диск → таблица «Tower records», лист `Scores`. Код живёт в проекте «Tower records board» на script.google.com, копия лежит в `tools/leaderboard.gs`. Если код поменялся, вставьте его в проект и обновите развёртывание: Начать развёртывание → Управление развёртываниями → карандаш → Новая версия. Адрес при этом не меняется.

Если `leaderboard_url` в `_config.yml` пустой, рекорды сохраняются только в браузере игрока. Как подключить таблицу заново:

1. Создайте Google Таблицу, например «Tower records».
2. Расширения → Apps Script. Замените код содержимым файла `tools/leaderboard.gs` и сохраните.
3. Начать развёртывание → Новое развёртывание → тип «Веб-приложение». Запуск от имени: «Я». Доступ: «Все». Разверните и разрешите доступ.
4. Скопируйте адрес веб-приложения (заканчивается на `/exec`) в `leaderboard_url` в `_config.yml`.

Записи появляются на листе `Scores`. Чтобы скрыть запись с сайта, впишите что угодно в её ячейку `Hidden` или удалите строку. Один и тот же человек с той же компанией занимает одну строку: лучший результат заменяет старый. Сайт держит таблицу в кэше до пяти минут, поэтому ручная правка на листе появится на сайте не сразу.
